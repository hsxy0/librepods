# BUG 修复报告：AirPods 5 连接后无弹窗

## 基本信息

- 日期：2026-09-23
- 报告人：WU / Codex
- 模块/功能：Android 蓝牙连接识别与底部连接弹窗
- 严重级别：中；耳机仍能建立系统音频连接，但应用内连接反馈缺失。
- 影响范围：已配对 AirPods 的连接提示，尤其是 BLE 邻近广播未到达或 AACP 控制通道未建立时。

## 问题描述与复现

1. 在 OnePlus PJZ110、Android 15 上安装 `1.0.0-airpods5.3-debug (81)`，保留已配对的 AirPods 5。
2. 断开耳机后重新连接；用户观察到应用没有连接弹窗。
3. 期望：已识别的 AirPods 连接时显示底部弹窗，关闭后下一次连接仍可显示。
4. 实际：提供的 `airpods_log_20260923_205829_939b96f4.txt` 在 20:58:20 与 20:58:54 记录了 ACL/A2DP 连接和 `HY的AirPods connected`，但没有 `Lid opened`；采集结束时 `aacpConnected=false`。这复现了“连接已被应用识别但弹窗触发事件缺失”的路径。

## 定位过程

- `AirPodsService.bleStatusListener.onLidStateChanged` 是原有 `showPopup` 唯一调用点；经典蓝牙连接广播仅尝试连接 AACP，不显示弹窗。
- `popupShown` 设为 `true` 后，弹窗关闭没有回调恢复状态；仅 AACP 断开广播清零。在 AACP 未建立时，曾显示过的弹窗会永久阻止后续显示。
- `PopupWindow.open` 吞掉 `WindowManager.addView` 异常，调用方仍把 `popupShown` 设为 `true`。
- 日志中的两次 `Connection already in progress` 相隔约 34 秒，超过现有 5 秒协程超时。`BluetoothSocket.connect()` 是阻塞调用，协程超时不能在阻塞期间中断它，导致连接保护状态长期不释放。

## 修复方案

- 连接广播对保存的设备地址直接识别，避免等待 SDP UUID；首次配对仍可通过 AirPods UUID 识别，其他设备不触发。
- 已识别连接事件调用现有 `showPopup`，与 BLE 开盖事件共用 `popupShown` 防重复。
- 弹窗关闭时重置状态；`PopupWindow.open` 返回实际打开结果，添加窗口失败时清理资源并允许下次重试。
- 阻塞式 AACP 建连启动独立的 5 秒关闭定时器；超时关闭 socket，使建连调用退出并释放重复连接保护。
- 保留 Xposed API 100 编译依赖，本次不修改 AACP 或 ATT 协议。

## 影响评估与回滚

- 影响模块：蓝牙连接广播、底部弹窗生命周期。相同连接事件重复到达时，只显示一个弹窗。
- 风险：系统连接但耳机盒仍关闭时也可能显示连接提示；真机确认后可根据体验调整触发时机。
- AACP 建连若因设备响应慢于 5 秒，会被关闭并等待下一次连接事件；原代码也设定 5 秒超时，本次使其真正生效。
- 回滚：撤销本次 `AirPodsService.kt` 与 `PopupWindow.kt` 的修改。

## 单元测试

- `AirPodsConnectionPopupPolicyTest` 覆盖已保存地址但 SDP 未完成、首次配对 UUID 识别、无关蓝牙设备忽略。
- 真正的系统悬浮窗创建与 12 秒自动关闭依赖 Android `WindowManager`；阻塞式 `BluetoothSocket.connect()` 需要真实蓝牙栈才能检验关闭是否及时解除阻塞。这两项由以下真机步骤验证。

## 手动验证步骤

1. 在手机系统设置中确认 LibrePods 的“显示在其他应用上层”权限已打开。
2. 打开 LibrePods → 设置 → 弹窗动画，确认“底部弹窗”已打开。
3. 关闭 AirPods 5 充电盒或从手机蓝牙中断开耳机；等待耳机显示已断开。
4. 打开盒盖并连接耳机，观察底部连接弹窗是否出现；应用日志应出现 `HY的AirPods connected`。
5. 点击弹窗关闭按钮，断开并重新连接耳机，确认弹窗可再次出现。
6. 等待弹窗自动关闭约 12 秒，再断开并重连，确认仍可出现。
7. 连接另一台非 AirPods 蓝牙设备，确认不会出现 AirPods 连接弹窗。
8. 关闭“底部弹窗”设置后重连 AirPods，确认不再显示；重新开启后应恢复。
9. 若 AACP 建连失败，等待至少 5 秒后重新连接；检查日志出现 `AACP socket connect timed out; closing socket` 或明确的建连结果，而不是持续出现 `Connection already in progress`。

## 验证结果

- 日志已复现触发链路缺口；自动化构建和真机验证结果待补。

## 遗留问题

- 提供的日志显示 AACP 控制通道未建立；超时修复解除连接保护卡死，但若真机更新后电量或降噪控制仍失效，需要单独采集建连失败原因。
